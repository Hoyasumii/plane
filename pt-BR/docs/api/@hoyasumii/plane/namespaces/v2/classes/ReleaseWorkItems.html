Defined in: src/api/v2/kernel/resource.ts:94

A resource is constructed with the transport and nothing else.

There is deliberately no bound scope. The pre-flat kernel took one — path placeholders a Workspace/Project locator filled once so methods could omit them — and it went with those locators: every id is a leading positional parameter now, and a second, invisible source of path ids is exactly what made a wrong URL well-formed.

extraPaths​

protected extraPaths: Record<string, string> = {}

Defined in: src/api/v2/kernel/resource.ts:81

Per-method override templates: a method whose URL is not built from path.

A catalog resource bridges add/remove at its parent's URL (.../releases/{release_id}/labels/, not its own .../releases/labels/); a report hangs off a sibling collection (Projects.roleDistribution). Keyed by method name, so urlFor(action, ids) makes the same choice at call time that the sweeps make when they check that method's leading parameters.

doCustomAction()​

protected doCustomAction<TResult>(action, options?): Promise<TResult>

Defined in: src/api/v2/kernel/resource.ts:312

A custom action whose response envelope is not this resource's own row, so doAction cannot type it — a summary, a bulk envelope, a presigned upload, a report.

Two URL shapes, matching the two that occur. With pk, the verb hangs off a row ({detailUrl}{action}/, exactly doAction's URL); without it, the action has a template of its own and goes through urlFor, which fills its extraPaths override or falls back to path. Either way action keys operations, so the query string is validated against the golden like any other call.

Prefer doAction whenever the response is a row of this resource; this is only for the envelopes that are not — it exists so those stop being hand-rolled transport.request blocks, one per resource.

formatPath()​

protected formatPath(template, action, pathParams): string

Defined in: src/api/v2/kernel/resource.ts:106

Fill template from pathParams, percent-encoding each value so an id can never inject extra URL segments.

action is the calling method's name and only feeds the error: a template key with no value behind it raises MissingPathIdError, which names the resource, the method, the template, the missing id and the ids that were supplied. An empty string counts as missing — it would otherwise build /projects//states/, a well-formed URL pointing at the wrong thing.
